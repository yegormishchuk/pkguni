# Лабораторная работа №3 — основы обработки цифровых изображений

**Мищук Егор. Вариант 15.**

По таблице задания вариант 15 объединяет строку «локальная пороговая обработка (2 метода) + адаптивная пороговая обработка» и столбец «нелинейные фильтры на порядковых статистиках».

## Реализация

- Локальные методы: **Ниблэк и Бернсен**.
- Адаптивный метод: **Саувола**; дополнительно — **Брэдли**.
- Порядковые фильтры: **медианный, минимальный и максимальный**.
- Предварительная медиана 3×3 перед выбранным методом.
- Настройка радиуса, коэффициентов, обработки границ и числа рабочих потоков.
- Загрузка своих изображений, drag-and-drop, четыре встроенных примера, сравнение «до/после», гистограммы, время обработки, отмена и экспорт PNG.

Алгоритм из лекции не предоставлен; по согласованию выбран метод Сауволы. Это выбор реализации, а не утверждение о содержании лекции.

## Запуск

Из корня общего репозитория:

```sh
python -m http.server 8000
```

Откройте <http://localhost:8000/lab3/>. Нужен современный браузер с ES-модулями, Canvas и module Web Workers. Открытие через `file://` не поддерживается.

Приложение не требует npm-зависимостей, серверной обработки или сборки. Все изображения обрабатываются в браузере и не отправляются на сервер. Исходный цвет переводится в яркость, прозрачность накладывается на белый фон. Декодирование поддерживаемых форматов выполняет браузер; пиксельные алгоритмы написаны вручную.

Ограничения загрузки: до 40 МиБ и 8 мегапикселей без скрытого уменьшения размера. Большие окна и дополнительные потоки увеличивают расход памяти. Радиус в интерфейсе 1–25, в математическом API 1–50. Reflect зеркалит без повторения граничного пикселя.

## Тесты

Требуется Node.js 20+:

```sh
npm run test:lab3
```

Либо `npm test` из этой папки. Проверяются все методы относительно независимого расчёта каждого окна, Clamp/Reflect, крупные окна относительно изображения, суммы квадратов без переполнения, прозрачность, валидация и совпадение однопоточной и многополосной обработки.

```sh

```

Вторая команда также использует Node.js и обновляет `measurements.json`, `comparison.png`, `histograms.png`. Время зависит от оборудования; F1 — от исходных PNG и параметров. [Анализ результатов](REPORT.md).

## Архитектура

- `index.html`, `style.css`, `js/main.js` — интерфейс, чтение изображения одним блоком через Canvas, визуализация и управление.
- `js/model/buffer.js` — обёртка над `Uint8Array`, яркость, Clamp/Reflect.
- `js/model/processing.js` — чистые математические функции; SAT суммы и суммы квадратов на Float64, скользящая гистограмма рангов.
- `js/model/tiles.js` — полосы с перекрытием, удаление служебных строк и сборка результата.
- `js/worker/processWorker.js` — обработка полосы в отдельном потоке.
- `js/services/processor.js` — запуск 1/2/4 потоков, передача буферов, прогресс, отмена.
- `tests/processing.test.js` — автоматические проверки математического слоя.

Алгоритмы ничего не знают о DOM. Canvas применяется для декодирования и вывода, но не для фильтрации; библиотечных фильтров, OpenCV, CSS-фильтров и попиксельных вызовов Canvas нет. Потоки получают полосы с перекрытием на радиус окна, поэтому результат не меняется при изменении числа потоков.

npx --yes serve@14 . --listen tcp://0.0.0.0:$PORT
